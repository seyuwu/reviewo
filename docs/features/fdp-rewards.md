# FDP: задания, танго, Марина и розыгрыши

Статус: первая версия реализована; локальные проверки завершены. 14 октября 2026 пользователь разрешил проверить все изменения и выложить их на прод. Дата решений: 14 октября 2026, Europe/Moscow.


## Уточнение выпуска: редактор заданий и аналитика

Это актуальная версия решений, уточняющая первоначальный фиксированный набор заданий.

- Steam убран. Семь стартовых заданий остаются, каждое можно редактировать, выключать, архивировать и возвращать из архива.
- Администратор создаёт до 50 действующих заданий. Можно менять название, описание условий, награду, событие выполнения, повторяемость и доступность. Для Telegram настраивается срок удержания тега от 1 до 168 часов. Рекламный тег общий и меняется в настройках программы.
- Автоматические условия: готовый профиль; поиск; создание пати; вступление; любое полезное действие с пати; регистрация приглашённого друга; его активность; семь дней одной недели; проверяемый тег Telegram. Источники уже существующих событий не меняются. Новое задание начинает начисляться после создания и новых подходящих событий; полная старая история не пересчитывается.
- Для остальных действий есть ручное задание: игрок отправляет текст или ссылку до 1000 символов, администратор принимает или отклоняет заявку с причиной. В заявке сохраняются условия и сумма на момент подачи. Изменение задания и отправка его в архив не меняют обещанную сумму уже поданной заявки.
- Повторяемость ограничена смыслом события: регистрация однократная; недельный бонус раз в неделю; для рефералов доступен период «за каждого нового друга»; остальные условия — один раз, раз в московский день или неделю. Ключ начисления не меняется при переименовании.
- Удаление в интерфейсе означает архив: задание исчезает у игроков, начисления и журнал сохраняются. Старый результат не пересчитывается после изменения цены награды. Повторное подтверждение заявки не начисляет деньги второй раз.
- Ручной ввод действует только в личном чате и состоянии отправки подтверждения. Переход в другой раздел очищает это состояние, не читая FSM для обычных нажатий. Фотографии в подтверждениях не принимаются; для них можно прислать ссылку.
- В боте задания имеют страницы по три, подробные условия и статус ручной заявки. Длинные условия можно прочитать целиком в отдельном временном сообщении. После проверки игрок получает уведомление с решением.
- По уточнению пользователя от 14 октября фразы Марины убраны со страниц заданий; описания условий подчёркнуты. Приветственное начисление показывается один раз после первого выполненного задания, а не только после заполнения профиля. Сообщение содержит «Выполнено задание…», «можно заработать ещё и выиграть призы» и «Сообщение удалится через 10 секунд». Срок удаления хранится в SQLite и переживает перезапуск бота.
- Уже заработавшие награды пользователи не получают повторное приветствие при обновлении. Проверка использует существующий индекс журнала и выполняется только в транзакции начисления, вне основных запросов поиска. Одновременное первое начисление двух заданий сериализуется блокировкой кошелька; создание кошелька использует INSERT ON CONFLICT вместо клиентского upsert.
- Кнопка проверки Telegram ставит статус PENDING и запускает автоматическую проверку имени/фамилии (не @username). Результат ручного запуска отправляется коротким сообщением с удалением через 10 секунд; очередные фоновые перепроверки сообщений не отправляют. Отдельный экран показывает PENDING/VERIFIED/MISSING/ERROR и время последней проверки. Кнопка обновления статуса не создаёт новую проверку. Админу отдельная заявка не требуется.
- Задание профиля пользователь отключил; выпуск кода не изменяет сохранённые настройки и не включает его обратно. По смыслу это необязательный стартовый бонус, а не ежедневное действие для уже зарегистрированного игрока.
- Проверки этих правок: 339 тестов API и 260 тестов бота прошли; сборка API, ESLint и проверка diff без ошибок. В тестах проверены конкурентные начисления, совместимость старого приветствия, удаление сообщения после перезапуска, все результаты Telegram и пять сценариев навигации после удаления пати.
- Аналитика: количество выполнений, уникальных игроков, сумма начислений, список «кто выполнил» с Telegram ID/именем, временем действия и начисления. Фильтры: задание, игрок, даты по Москве. Видны также архивные задания. Покупки и возвраты исключены из статистики заданий. Страницы: по 100 начислений, по 50 заявок.
- Право управления наградами проверяется сервером по текущему аккаунту и его подтверждённой Telegram-привязке. ID из запроса клиента не используется. ADMIN сайта также сохраняет доступ. Обычные админ-маршруты сайта по-прежнему требуют ADMIN.

## Изоляция и проверка нагрузки

- HTTP наград в боте имеет отдельные четыре соединения; синхронизация журналов — своё одно соединение и отдельную сессию уведомлений. Занятые наградами соединения не отнимают основной HTTP-пул поиска.
- PostgreSQL: основной пул приложения сохраняется; наградные HTTP-операции используют отдельный пул до трёх соединений; аналитика — отдельное одно; фоновая обработка — два. SQL ограничен таймаутами, внешние проверки проходят вне транзакций.
- Фоновая порция — до 100 событий, уменьшается при большом числе заданий, чтобы ограничить работу одной транзакции. Списки и фильтры индексированы; кошелёк читает только текущие ключи выполнения, без выгрузки всей истории рефералов или заявок.
- Аналитика загружается только при открытии её вкладки, фильтры применяются кнопкой, обновление раз в 30 секунд только для активной вкладки.
- Проверен настоящий граф Nest: 320 зарегистрированных маршрутов, 23 маршрута наград, пересечений с остальными нет.
- Локальная нагрузочная проверка на реальных сервисах/API-запросах PostgreSQL с 20 000 начислений: поиск и пати p50 9,39 мс без аналитики / 9,60 мс с аналитикой; p95 13,08 / 12,22 мс. При занятом на 500 мс соединении аналитики основные операции завершились за 12,36 мс. Redis в этом замере заменён заглушкой; это замер работы сервисов и базы, не обещание времени ответа продакшена.
- EXPLAIN подтверждает использование reward_ledger_task_time_idx. Отдельный транспортный тест насыщает HTTP-пул наград и проверяет доступность обычного запроса профиля.
- Браузер проверен на 390 и 1280 px: создание, изменение, выключение, архив/возврат, статистика, фильтр игрока и ручное подтверждение. Нет ошибок выполнения или горизонтального переполнения. Проверены доступ разрешённого USER-аккаунта и отказ пользователю без прав; запросы аналитики до открытия вкладки не выполняются.

## Запрос и назначение

Игрок получает внутреннюю валюту за полезные действия, покупает билеты и участвует в розыгрышах призов, заданных администратором. Основной цикл: действие → подтверждение → начисление → билет → случайный результат → выдача приза. Задания учитываются пассивно, даже если пользователь никогда не открывал раздел наград. Нажатие на задание не является условием начисления. Основные запросы поиска и пати не должны ждать наград, внешних проверок или уведомлений.

Разработка и первичные проверки выполнены локально. Существующий поиск, регистрации, турниры, компании друзей и рефералы должны сохранить поведение. Документ фиксирует принятые решения, состояние реализации и вопросы для последующей правки.

## Персонаж и названия

- Рабочее название раздела: «Танго от Марины». Пользователь упоминал Марию и Марину; пока выбрана Марина, имя редактируется.
- Валюта: «танго»; «тангусики» — допустимое разговорное обращение.
- Своя взрослая 2D аниме-героиня: зелёные акценты, выразительная мимика, узнаваемая одежда. Не копия персонажа Ozon.
- Разные изображения: приветствие/баланс; заработок с монетами и листьями; радостный розыгрыш с сокровищницей. Дополнительные состояния могут использовать те же картинки с другими фразами.
- Короткие фразы выбираются из настроенных списков для конкретного экрана; без повторения последней фразы при наличии альтернативы.
- При переходе в раздел наград меняется картинка текущей панели. При выходе возвращается обычная картинка бота. Фразы остаются текстом подписи, не вшиваются в изображение.
- Отдельные настройки: заголовок раздела, имя персонажа, название/формы валюты, изображения, фразы, названия и суммы заданий. Внутренние ключи нейтральные (`Rewards`, `RewardWallet`, `Giveaway`), переименование не меняет историю или условия купленных билетов.

## Экономика первой версии

Танго зарабатываются бесплатно; продажа за деньги, переводы между пользователями, вывод и обмен на деньги не входят в первую версию. Баланс целочисленный, неотрицательный. По умолчанию танго не сгорают. Пример цены билета — 10; цена задаётся отдельно для каждого розыгрыша. Суммы ниже являются изменяемыми стартовыми настройками.

| Ключ | Задание | Награда | Повторяемость и подтверждение |
| --- | --- | --- | --- |
| profile_ready | Заполнить игровой профиль | 5 | Один раз после указания позиций и MMR |
| daily_party | Первый поиск или создание пати | 5 | Один раз на московский день; успешная реальная операция, не открытие кнопки |
| referral_ready | Пригласить зарегистрировавшегося друга | 5 | Один раз на нового приглашённого, после готового профиля |
| referral_active | Друг начал пользоваться пати | 15 | Один раз на приглашённого, после поиска или вступления |
| first_party_join | Найти первую пати | 5 | Один раз после успешного вступления в чужую пати |
| weekly_party | Искать пати каждый день недели | 10 | Семь разных московских дней в одной календарной неделе, понедельник–воскресенье; один бонус на неделю |
| telegram_tag | Тег в имени Telegram | 2 | Ежедневно после повторных проверок своего профиля |

Дополнительные задания для последующего расширения: участие в состоявшемся турнире; первый сыгранный матч с подтверждённым результатом; полезный отзыв после ручного решения. Это идеи, а не опубликованные автоматические задания. Не выдавать награды за каждое сообщение, нажатие, отмену/перезапуск или бесконечные ежедневные открытия бота. Если источник события не даёт надёжного подтверждения, задание не публикуется как автоматическое.

## Пассивный учёт и производительность

- Источник истины для баланса, операций и билетов — PostgreSQL API. SQLite бота содержит только исходные события/доставку и кэши интерфейса.
- Использовать уже записываемые события воронки и реферальные этапы. Синхронизация порциями и фоновые обработчики; основной ответ бота не ждёт HTTP наград.
- Если нужны новые события, сохранять их вместе с существующей операцией/в журнал, без отдельного внешнего запроса из горячего обработчика.
- Каждый источник имеет устойчивый ID, тип, пользователя и время фактического действия. Начисление защищено уникальным ключом задания/пользователя/периода либо приглашённого.
- Повторная доставка после сбоя не создаёт повторные начисления. Ошибки наград не отменяют успешную регистрацию, поиск или вступление.
- Обработка ограничена размером порции, временем, индексированным курсором и частотой. Без полного сканирования истории на каждое нажатие и без запросов Telegram в поиске.
- Внешние проверки и синхронизация используют отдельный HTTP-пул, ограниченную параллельность, таймауты, повторы и задержку при ошибках.
- Функция отключаема флагом. По умолчанию не включать на прод автоматически.
- Старые поиски и приглашения не начислять массово при первом запуске. Точка начала кампании фиксируется при включении. Если задание профиля включено, уже готовый профиль получает его награду один раз при первом обращении после запуска, без открытия раздела наград. Если выключено, начисления за профиль нет. Приветственное сообщение отправляется один раз после первого выполненного задания; старые начисления также учитываются при защите от повторного приветствия. Неактивным аккаунтам награда массово не начисляется.
- Начисления фоновые, поэтому на экране возможна короткая задержка. UI показывает, что действия учитываются автоматически; кнопки «забрать награду» не нужны.

## Ники и владение аккаунтом

Telegram: проверять имя/фамилию известного боту пользователя по устойчивому Telegram ID. Не принимать произвольный чужой username как доказательство. Искать точный тег `@FDPdotabot` без учёта регистра и с границей после имени, чтобы `@FDPdotabot_fake` не проходил.

Steam-задание и пользовательские маршруты Steam убраны по уточнённому запросу пользователя. Ключ Steam для этого выпуска не нужен.

Первая успешная проверка запускает наблюдение на 24 часа (срок меняется в задании). Затем награда за выбранный период требует повторной успешной проверки. Следующая проверка назначается через случайные 3–4 часа. Проверки не доказывают непрерывную историю имени. Удаление тега останавливает будущие начисления; уже заработанное и билеты не отбираются. Ошибка провайдера — «не удалось проверить», повторить позже; не считать отсутствием тега. Ручная очередь — для спорных случаев, с причиной решения и журналом администратора.

## Розыгрыши

Администратор задаёт название, описание, картинку, реальные призы, количество победителей, цену билета, начало/конец по московскому времени, лимит билетов на человека, правило повторных побед, условия и срок получения. В черновике всё редактируется. Публикация требует заполненных условий. После первых билетов материальные условия фиксируются.

Состояния: `DRAFT → OPEN → CLOSED → DRAWN`, отдельно `CANCELLED`. Окончание приёма автоматическое по серверному времени. Нажатие админом «Определить победителя» допускается только после закрытия. При отсутствии билетов результат пустой, подставных победителей нет.

Покупка — одна транзакция: блокировка кошелька/розыгрыша, проверка срока и лимита, списание, запись покупки и уникальных пронумерованных билетов. У запроса есть ключ повторного нажатия. Старое подтверждение покупки не должно списывать по другой цене.

Перед выбором фиксируется список и контрольная сумма билетов. Сервер использует криптографический случайный выбор с одинаковым шансом каждого билета. Для нескольких призов правило повторных побед фиксируется заранее; выбранные билеты исключаются, а при уникальных победителях исключаются все билеты победившего пользователя.

Результат сохраняется один раз под блокировкой. Повторное нажатие возвращает тот же результат. Прозрачная история: номер билета, приз, дата выбора, статус выдачи; персональные идентификаторы не публикуются без необходимости. Выдача отмечается отдельно. Отмена возвращает фактически списанную сумму ровно один раз, независимо от последующих цен.

## Интерфейс игрока

Главное меню: отдельная кнопка раздела наград, без обязательного запроса кошелька для обычного поиска. Раздел: картинка Марины, фраза, баланс, доступный розыгрыш, задания/розыгрыши/мои билеты/история/назад.

Заработок: другая картинка Марины с монетами/листьями; доступные задания выше выполненных, понятные состояния «доступно», «учитывается автоматически», «на проверке», «выполнено сегодня», «повторить позже». Переходы ведут к существующим действиям бота. Условия и сумма видны до действия.

Розыгрыши: радостная Марина и сокровищница, призы/срок/цена/правила, свои билеты. Покупка сначала показывает количество, общую цену, остаток баланса и лимит, затем подтверждение. После закрытия покупка недоступна; видны ожидание итогов или сохранённый результат.

История: страницы начислений и списаний с причинами и временем; свои покупки и номера билетов; результаты/выдача. Списки ограничены и разбиты по страницам.

## Администратор

Веб-админка: настройки программы и персонажа, суммы/доступность заданий, черновики/публикация/отмена розыгрышей, закрытие/подведение итогов, просмотр билетов и результатов, выдача призов и ручная проверка. Быстрый вход из бот-админки. Все права проверяются API на сервере; бот-allowlist не заменяет веб-роль автоматически. Ручные решения и изменения записываются с исполнителем.

## Как узнают о наградах

В первой версии: кнопка главного меню, одно сообщение о приветственном начислении и сообщение победителю со ссылкой на розыгрыш. Уведомления находятся в отдельной долговечной очереди, отправка не входит в транзакцию начисления. Ежедневные мелкие начисления видны в балансе и истории, отдельного сообщения за каждое нет. ## Реализация и ограничения первой версии

1. API: `apps/api/src/modules/rewards/`. Все состояния финансовых операций сохраняются в PostgreSQL. Миграция `20261014010000_fdp_rewards` добавляет собственные таблицы и триггеры только на уже фоновые источники — рефералы и историю поиска. Условия опубликованного розыгрыша фиксируются сразу при публикации, что строже минимального правила «после первого билета».
2. Бот: `rewards_sync.py` читает существующие SQLite-журналы с курсорами. Размер объединённой порции — до 100 событий. Курсор подтверждается после успешной записи на API; повторная доставка безопасна. Для уже готовых профилей используются индекс времени последнего обращения и таблица отправленных приветственных событий. Полного сканирования всей истории на каждое нажатие нет.
3. Короткий отменённый поиск не даёт ежедневную награду. Поиск подтверждается после двух минут или успешного вступления. События API захватываются в транзакции уже фоновой записи аналитики, поэтому поздняя запись после сбоя не пропускается временным курсором.
4. PostgreSQL-обработчик запускается раз в 30 секунд, не перекрывает собственные проходы и обрабатывает до 100 событий. При большом числе заданий порция уменьшается, ограничивая работу прохода. Его отдельный пул имеет максимум два соединения. Глобальная блокировка обработки и уникальные ключи журнала защищают несколько экземпляров API. Недельный бонус читает отдельную таблицу уникальных дней активности, без обхода всей истории игрока.
5. Внешние проверки: не больше трёх за проход, последовательно, таймаут каждой пять секунд. Сетевая проверка выполняется вне транзакции; задание предварительно получает сохранённую аренду. Ошибки провайдеров не отнимают награды. У бота отдельный HTTP-пул синхронизации и отдельная Telegram-сессия для наградных уведомлений.
6. Граница суток — 00:00 МСК. Соединения Prisma фиксируют UTC: локальный тест обнаружил, что адаптер при другом часовом поясе соединения мог записывать дату со смещением на три часа. Даты UI явно показываются по Москве.
7. Уведомления выдаются порциями до десяти с арендой. Подтверждение доставки и локальная запись отправленного сообщения позволяют повторить подтверждение после сбоя API. После шести неудачных отправок автоматические попытки останавливаются. Сбой между фактической отправкой Telegram и сохранением её ID может дать повторное сообщение; финансовые начисления при этом не повторяются.
8. Максимум билетов в одном розыгрыше — 100 000; максимум на пользователя настраивается до 1000. Максимум призов/победителей — 20. Билеты не переводятся. Отмена запускает возвраты порциями по 100, повторное выполнение не возвращает сумму дважды.
9. Списки: игрок видит последние десять розыгрышей; история операций и свои номера билетов имеют страницы. Админка показывает последние 50 розыгрышей и первые 50 ожидающих/неудачных проверок; список билетов имеет страницы по 100. Полные условия длинного розыгрыша можно открыть отдельными текстовыми сообщениями в боте.
10. Имя персонажа, название раздела/валюты, тег, фразы, названия заданий, суммы и доступность изменяются через админку. В первой версии изображения — три файловых ресурса проекта; их замена выполняется заменой PNG с тем же именем. Кэш учитывает содержимое изображения. Веб-загрузка изображений не входит в эту версию. Новые задания создаются в админке по поддерживаемым событиям или с ручной проверкой.

## Проверки имени Telegram: подготовленные изменения 15 октября 2026
