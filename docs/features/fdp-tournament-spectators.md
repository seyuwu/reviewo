# Две минуты на вход зрителей в турнирное лобби

## Сценарий

Капитан назначенной стороны создаёт лобби в Dota и сохраняет название, пароль и настройки на странице матча. Оба капитана отдельно отмечают, что все пять игроков их команды уже в лобби и настройки проверены, затем подтверждают готовность. Первый капитан не запускает ожидание: оно начинается только после второго подтверждения.

Если зрители разрешены настройками матча, начинается этап **«Вход зрителей»** с отсчётом **02:00**. На странице видны подтверждения капитанов и таймер; после двух минут капитан стороны, создавшей лобби, запускает игру в Dota и нажимает **«Подтвердить старт матча»** на сайте. Если зрители отключены, после двух подтверждений матч сразу готов к старту.

FDP не проверяет состояние клиента Dota: факт входа десяти игроков подтверждают капитаны. Название и пароль по-прежнему доступны только участникам матча; капитан передаёт их зрителям отдельно и просит занять место зрителя. Эта функция не создаёт DotaTV-ссылку и не запускает игру автоматически.

## Хранение и ограничения

- Миграция `20261006120000_tournament_spectator_admission` добавляет `SPECTATOR_ADMISSION`, `captainAReadyAt`, `captainBReadyAt`, `spectatorAdmissionEndsAt` и индекс для сканирования сроков.
- `POST /dota/tournaments/:slug/matches/:id/confirm-lobby` требует `{ "playersReady": true }`. Подтверждать может только капитан соответствующей команды. Обычные игроки сохраняют доступ к деталям, результатам и спорам.
- Капитан — текущий владелец связанной постоянной команды либо создатель отдельного состава этого турнира. Подтверждение требует двух полных составов с пятью разными ролями.
- Подтверждения выполняются в транзакции с блокировкой строки матча. Одновременные нажатия не теряют второе подтверждение; повторные нажатия не продлевают ожидание.
- Сервер хранит абсолютный конец ожидания и не принимает ранний старт даже при прямом запросе. Перезагрузка страницы и перезапуск API не сбрасывают таймер. После ожидания остаётся 15 минут на старт, затем матч требует разбора модератором.
- Срок подачи результата начинается только при подтверждении старта. Переигровка сбрасывает обе готовности, пароль и ожидание зрителей.
- Миграция сохраняет право старта уже подтверждённых матчей старого формата. Им не добавляется ожидание задним числом.
- Страница считает секунды по серверному времени и тихо обновляет подготовительные стадии раз в пять секунд только в видимой вкладке. Старый ответ обновления не перезаписывает новое действие игрока. Чтение деталей не сканирует сроки всех матчей: запись происходит только при переходе текущего матча; общий фоновый проход остаётся раз в 30 секунд.

## Локальная проверка

Интеграционные тесты `tournament-spectators.integration.test.ts` работают только с отдельной локальной базой `fdp_spectator_qa`, заданной через `TOURNAMENT_TEST_DATABASE_URL`. Они проверяют два подтверждения, одновременные нажатия, повторные нажатия, ранний старт, права капитанов, выключенных зрителей, отсутствие утечки пароля, неполные составы, истечение сроков и переигровку.

При выкладке нужна обычная миграция API и обновление сайта вместе с API. На стадии ожидания сайт регулирует подтверждение старта; капитан технически может запустить игру в самом клиенте раньше, поэтому должен соблюдать регламент турнира.
