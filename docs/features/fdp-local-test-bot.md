# Изолированный локальный Telegram-бот FDP

Конфигурация: `apps/dota-bot/.env.local-test` (игнорируется Git).
Вставить токен **отдельного бота из BotFather** в `DOTA_BOT_TOKEN`, свой числовой
Telegram ID — в `DOTA_BOT_ADMIN_IDS`. ID можно узнать командой `/local_id`
в тестовом боте. Остальные секреты генерируются локально при первом запуске.

Запуск из корня репозитория в PowerShell:

```powershell
# Docker Desktop должен работать. При первом запуске подготовить базы и сборку:
./apps/dota-bot/start-local-test.ps1 -Prepare
# Последующие запуски:
./apps/dota-bot/start-local-test.ps1
# Остановка API, сайта и бота; данные сохраняются:
./apps/dota-bot/stop-local-test.ps1
```

Supervisor запускается скрыто и ждёт заполнения файла. После сохранения токена
проверяет `getMe` и запускает polling. При изменении токена или ID администратора
перезапускает локальный API/бота. Токен `@FDPdotabot` отклоняется до изменения
webhook или polling. Удаление токена из файла останавливает тестового бота.

Локальные адреса фиксированы в launcher:

- Сайт: `http://127.0.0.1:3003`
- API: `http://127.0.0.1:32207`
- PostgreSQL: `127.0.0.1:32208`, база `fdp_local_bot`
- Redis: `127.0.0.1:32209`
- SQLite, статус и логи: `apps/dota-bot/.local-test/` (игнорируется Git)

Docker Compose использует отдельный проект `fdp-local-test-bot`, свои volumes
PostgreSQL/Redis и loopback-порты. Данные с прода и прежних QA-баз не копируются.
Подготовка автоматически открывает поиск и сообщество только в `fdp_local_bot`:
новая база по умолчанию содержит закрытые launch gates. Скрипт открытия проверяет
точное локальное подключение и отказывается работать с другой базой.
Остановка supervisor оставляет контейнеры базы доступными; их можно остановить
без удаления данных:

```powershell
docker --context desktop-linux compose -p fdp-local-test-bot -f apps/dota-bot/local-test.compose.yml stop
```

Дочерние процессы получают очищенное окружение с фиксированными локальными
подключениями. API запускается из `.local-test/`, где нет `.env` проекта.
Discord, waitlist-бот и Google Sheets не подключаются. API_BIND_HOST в API
позволяет этому запуску слушать только loopback; без этой переменной используется
прежний способ привязки сервера. Сайт также слушает только `127.0.0.1`.

Сам Telegram остаётся внешним сервисом: сообщения тестового бота и фотографии
проходят через Telegram. Регистрация, подбор пати, очередь рассылок и аналитика
работают с локальными базами. Telegram ID одного человека может присутствовать
и на проде, и в тестах, но записи, сессии и очереди не общие.

В этом окружении используются уже установленные Node.js и bundled Python Codex,
а Python-зависимости — из `tmp/bot-qa-deps`. Статус без секретов записывается в
`.local-test/status.json`, ошибки запуска — в `supervisor-error.log`.
