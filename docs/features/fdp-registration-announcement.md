# Сообщение после первой регистрации в боте

В Telegram: `/admin` → **«Сообщение после регистрации»**. Администратор отправляет
текст или одно фото с подписью, выбирает срок удаления, смотрит предпросмотр,
может отправить тест себе и нажимает **«Сохранить и включить»**. Форматирование
Telegram сохраняется; используются те же лимиты, что у рассылок: 4096 единиц
UTF-16 для текста, 1024 для подписи, удаление через 1 секунду — 47 часов.

**«Отключить отправку»** сохраняет шаблон для дальнейшего включения через
предпросмотр. **«Убрать сообщение»** отключает отправку и очищает шаблон.
По умолчанию отправка отключена. Черновик ничего не меняет до сохранения.

В этих же настройках можно включить или выключить кнопку **«Поделиться»** под
приветственным сообщением. По умолчанию кнопка включена. Она открывает обычный
выбор получателей Telegram и подставляет текст приглашения с личной ссылкой
получателя приветствия. Используется тот же реферальный код, что в «Пригласить
друзей»: он не даёт вход в аккаунт, а учитывает новых пользователей и их дальнейшие
этапы регистрации. Inline-режим и изменения в BotFather не нужны.

Обычное окно Telegram поддерживает простой текст: личная ссылка вставляется после
«я тебе рекомендую бота -», без дублирования отдельной строкой. Переход по ней
учитывается как приглашение. Получатель выбирается
пользователем, сообщение отправляется только после его подтверждения в Telegram.
Выключение кнопки действует на новые и ещё не доставленные приветствия; уже
отправленные сообщения сохраняют свою кнопку до удаления сообщения.

Сообщение резервируется один раз после успешного создания Dota-профиля и
подключения Telegram, включая успешный повтор подключения. Открытие `/start`,
редактирование профиля, запуск поиска и повторная регистрация того же Telegram ID
не создают повторного объявления. При первом обновлении бота ранее зарегистрированные
пользователи помечаются как уже обработанные. Регистрации во время отключённой
отправки также помечаются; последующее включение не запускает рассылку задним числом.

SQLite хранит настройки и очередь доставки между перезапусками. Очередь получает
снимок шаблона и срока на момент регистрации; изменение шаблона влияет на следующие
регистрации. Отключение отменяет ещё не отправленные сообщения. Уже доставленные
удалятся по своему сроку, который считается отдельно от времени доставки каждому
получателю. Тестовое сообщение также удаляется по выбранному сроку.

Фоновый worker использует общую блокировку временных уведомлений пользователя,
чтобы дождаться коротких подсказок. В обработчик регистрации добавляется только
небольшая запись SQLite; дополнительных запросов API или Telegram в нём нет.
Настройка доступна только Telegram ID из `DOTA_BOT_ADMIN_IDS` и только в личном чате.
Сохранение шаблона не запускает массовую рассылку.

Успешно доставленные и отменённые записи сохраняют минимальную отметку для
дедупликации; текст и фото удаляются из обработанной очереди. Telegram не имеет
ключа идемпотентности для отправки: после неоднозначной сетевой ошибки или
перезапуска во время отправки сообщение не повторяется, чтобы не создать дубль.
Явный отказ из-за ограничения скорости повторяется после разрешённого срока.

Изменение затрагивает только бот. Таблицы SQLite создаются автоматически;
миграция PostgreSQL, изменение сайта и перезапуск API не нужны.
