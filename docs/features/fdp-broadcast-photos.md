# Фото в рассылках FDP

В личном чате администратора: `/admin` → «Создать рассылку» → отправить текст
или **одну картинку как фото с подписью** → выбрать срок удаления → проверить
предпросмотр → «Отправить тест себе» → «Отправить всем».

В предпросмотре можно добавить, заменить или убрать картинку. «Изменить текст»
сохраняет текущую картинку и меняет подпись. При добавлении/замене фото без
подписи сохраняется ранее введённый текст. Можно отправить фото без текста.
Если убрать картинку без подписи, бот попросит ввести новый текст.

Предпросмотр показывает текст с форматированием целиком, без обрезания первых
120 символов. Для длинного объявления используются страницы и кнопки «Текст →»
и «← Текст». Деление относится только к предпросмотру: подтверждённая кампания
содержит полный исходный текст и все entities. «Отправить тест себе» показывает
реальное сообщение без служебных строк предпросмотра.

Подпись ограничена 1024 единицами UTF-16, обычный текст — 4096. Проверка
выполняется при вводе и создании кампании. Перед массовой отправкой доступна
тестовая отправка того же фото и подписи с тем же сроком удаления. Документы,
видео и альбомы не принимаются. Форматирование, применённое в Telegram к тексту
или подписи, сохраняется: entities передаются в тест и массовую отправку.
Написанные вручную `**звёздочки**` или HTML-теги не разбираются как разметка:
нужно выделить текст и применить форматирование средствами Telegram.

Фото хранится как Telegram `file_id` в nullable-поле `broadcast_campaigns.photo_file_id`.
Форматирование хранится в `entities_json` с пустым массивом для старых кампаний.
Пробелы и переносы исходного текста сохраняются, чтобы не смещать UTF-16 offsets
форматирования, особенно рядом с emoji. При редактировании текста его entities
полностью заменяются; добавление фото без подписи сохраняет текст и его entities.
SQLite добавляет поле при инициализации; старые кампании остаются текстовыми.
Сервер не скачивает картинку, не хранит её байты и не загружает файл заново для
каждого получателя. Подтверждённая очередь вместе с фото сохраняется после
перезапуска бота; незавершённый черновик находится в существующем MemoryStorage.

Тест и worker используют один метод отправки: `send_photo` для фото и
`send_message` для текста. Worker сохраняет ID доставленного сообщения в
существующую очередь удаления. Фото и подпись удаляются целиком одним
`delete_message`; отсчёт начинается отдельно после доставки каждому игроку.
Повторные попытки и ограничение скорости работают в существующем worker.

Под каждым тестовым и массовым объявлением есть кнопка «Удалить это сообщение».
Она удаляет конкретное сообщение только из личного чата нажавшего. Для массовой
кампании сохраняются Telegram ID доставленного сообщения и время первого нажатия;
повторный тап не увеличивает счётчик. Счётчик «удалили вручную» виден в сводке
последней рассылки в `/admin` и в отчёте о завершении кампании. Ручное удаление
не меняет запланированный TTL для остальных получателей.

Доступ к вводу, тесту и подтверждению имеют только `settings.admin_ids` в личных
чатах. `/start` и другие команды не перехватываются обработчиком фото.
Изменение не добавляет вызовов Telegram/API в поиск или подбор пати.

Проверки выполняются локально с временной SQLite и подменённым транспортом
Telegram: приём фото после удаления входящего сообщения middleware, переходы
черновика, права, лимиты подписи, двойное подтверждение, миграция старой очереди,
перезапуск, повтор доставки и срок удаления. Реальная рассылка не выполняется.
