# Просмотр пати администратором

Администратор открывает `/games/parties` через пункт «Все пати» в меню «Команды и пати». Это отдельная страница Games, не раздел админки.

Список включает действующие Dota-пати и постоянные команды, в том числе закрытые. Истёкшие, удалённые и объединённые в другой состав пати не показываются. Есть фильтры по типу состава; отображаются участники, позиции, капитан, режим вступления и срок действия. По кнопке открывается обычная страница `/dota/teams/[slug]`.

Если администратор не состоит в открытой пати, вместо заглушки «чат только для участников» он видит сообщения в режиме чтения. Обновление — кнопкой; старые сообщения загружаются отдельно. Администратор, который уже состоит в пати, использует обычный чат участника.

## Доступ и побочные эффекты

- `GET /admin/parties` и `GET /admin/parties/:partyId/chat/messages` защищены `JwtAuthGuard` и `AdminGuard`. Роль берётся из актуальной записи пользователя в базе, не из параметров браузера.
- Сервис дополнительно проверяет роль ADMIN. Обычные пользователи и TOURNAMENT_MODERATOR не получают доступ.
- Просмотр сообщений не создаёт членство, не отправляет сообщения/уведомления и не добавляет служебную подсказку в старые чаты.
- Правила обычного чата и WebSocket-комнат остаются прежними: писать в чат и подключаться к комнате участников можно только через штатный сценарий членства.
- Список использует курсор и возвращает до 50 составов (интерфейс — 25). Чат возвращает до 100 сообщений (интерфейс — 50). Все страницы доступны через догрузку.
- Запросы выполняются при открытии и по кнопкам, без нового фонового опроса. Чаты запрашиваются по существующему индексу `partyId, createdAt`. Новых миграций и задач автоподбора нет.
- Ответы API содержат `Cache-Control: private, no-store`; кэш нового списка и административного чата в браузере удаляется после закрытия соответствующего компонента.

## Регрессионная проверка

`apps/api/scripts/smoke-admin-parties.mjs` запускается против локального API и отдельной базы `fdp_admin_qa` с `NODE_ENV=development`. Скрипт отказывается работать с внешним API или другой базой. Тестовый API нужно запускать без рабочих Telegram/Discord-токенов. Созданные игроки и составы удаляются в `finally`.

Проверяет обычное создание пати, конкурс за один слот, смену/освобождение роли, полную пати, ссылки-приглашения, заявки и одобрение, WebSocket-события состава и чата, смешанный автоподбор сайта/Telegram, ограничения MMR, объединение пати, фильтры/пагинацию, доступ к закрытому чату, снятие ADMIN и отсутствие записей при административном чтении.

При проверке 5 октября 2026 года прошли 106 HTTP-проверок этого скрипта и 92 запроса сценариев `smoke-tournament-squads.mjs`, 271 тест API, 44 теста Telegram-бота и 36 тестов фронтенда. Найден и исправлен редирект `/games/parties` в `/dota/parties` на Dota-домене; добавлен отдельный тест маршрута.

После добавления запрета повторного автоподбора скрипт также проверяет сохранение исключения при перезапуске поиска с сайта и Telegram, ручной вход, заявки, ссылки, личные приглашения и запрет обхода через слияние пати. Повторный прогон: 143 HTTP-проверки, 273 теста API; запрет переносится на оставшуюся пати после слияния. Автопоиск Telegram не получает новых ручных кнопок.

Перед production-деплоем 5 октября повторно прошли 273 теста API, 44 теста бота, 36 тестов фронтенда, production-сборка сайта, ESLint изменённых файлов и проверка типов. Последовательные прогоны на изолированном локальном API: 146 HTTP-проверок административного просмотра/пати и 92 запроса турниров. Количество запросов первого скрипта зависит от числа проверок ожидания фонового слияния. Локальная медиана запросов — около 30 мс; это не нагрузочный тест production.
